# Role

You are a senior full-stack TypeScript engineer and software architect.

Your task is to design and implement a production-ready but intentionally simple booking platform for a small barber shop.

The application will initially be used by **one barber**.

The expected traffic is low, but the application must be secure, maintainable, easy to deploy, and designed so that it can grow later without requiring a complete rewrite.

Do not overengineer the application.

Prefer simple, explicit, well-tested solutions.

---

# Main Goal

Build a web application where:

## Customers can

* View available barber services
* View available dates and time slots
* Book an appointment
* Enter:

  * name
  * phone number
  * optional email
* Receive confirmation that the booking was created
* Never see another customer's personal information
* Never access administration functionality

Customers do NOT need accounts in version 1.

---

# Barber can

The barber must have a protected admin account.

After logging in, the barber must be able to:

* View today's appointments
* View appointments by day
* View appointments in calendar/list form
* View customer:

  * name
  * phone
  * optional email
* Confirm an appointment
* Cancel an appointment
* Mark appointment as completed
* Mark appointment as no-show
* Change appointment date/time
* Create an appointment manually
* Edit appointment notes
* Block specific time periods
* Block an entire day
* Configure weekly working hours
* Configure breaks
* Manage services
* Set service duration
* Set service price
* Enable/disable services

Only authenticated admin users may access these operations.

# Timezone

The initial deployment and business timezone is:

Europe/Sofia

All date/time handling must be deliberate and safe.

Prefer storing timestamps in UTC in PostgreSQL and converting them correctly to Europe/Sofia when displaying or calculating availability.

Be careful with daylight saving time.

Do not implement time calculations using naive string manipulation.

Use a reliable date/time library if necessary.

---

# Booking Availability Logic

This is one of the most important parts of the application.

The backend must determine available time slots.

The frontend must NEVER be the source of truth for availability.

Availability must take into account:

* selected service duration
* weekly working hours
* blocked times
* existing bookings
* cancelled bookings
* configured slot interval
* current date/time

Example:

Working hours:

09:00 - 18:00

Break:

13:00 - 14:00

Existing booking:

10:00 - 10:30

Selected service duration:

30 minutes

The API should return only valid available slots.

---

# Prevent Double Booking

This is CRITICAL.

Two customers may attempt to book the same slot at almost the same time.

Do not rely only on:

"check if available → insert booking"

because that creates a race condition.

Design proper database-level protection / transactional logic so two overlapping appointments cannot accidentally be created.

Explain the chosen strategy before implementing it.

Use PostgreSQL capabilities where appropriate.

The final system must protect against concurrent booking requests.

---

# Appointment Duration

Appointments are based on service duration.

Example:

Haircut:
30 minutes

Hair + beard:
60 minutes

If a customer selects a 60-minute service, the entire 60-minute window must be free.

Do not only check whether the starting time is available.

Check the entire appointment interval.

# Important Working Rules

When working inside Claude Code:

* inspect files before editing them
* preserve existing good code
* do not rewrite working parts unnecessarily
* run tests after meaningful changes
* run TypeScript type checking
* run linting
* inspect errors instead of hiding them

* do not disable TypeScript strictness to make errors disappear

* do not leave critical functionality as TODOs

If something is ambiguous but not critical, choose a sensible default and document it instead of stopping the entire implementation.
